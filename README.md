# Thin Market Monitor

Windows-приложение для фильтрации спотовых листингов, мониторинга резкого роста и просмотра минутных свечей. [Скачать Windows x64 EXE](https://github.com/ksen0v/thin-market-monitor/releases/latest/download/ThinMarketMonitor-win-x64.exe). Запустите файл из папки, доступной на запись. Приложение сохраняет настройки в `%LOCALAPPDATA%\ThinMarketMonitor\settings.json`.

## Фильтр и выбор рынка

- ✓ — активный листинг обязателен. Несколько ✓ дают пересечение.
- × — активного листинга быть не должно. Любая из бирж с × исключает совпадение.
- — — биржа игнорируется при сравнении. При наличии ✓ она не участвует и в выборе рынка. Если ✓ нет, исходный список — объединение доступных каталогов бирж без отметок. Пустой фильтр даёт такое же объединение.
- При ошибке любого каталога с ✓ или × список и сигналы приостанавливаются. Состояние каталога видно на главном экране, подробности — в подсказке. Повторная загрузка выполняется каждые пять минут и по кнопке.
- Идентификатор монеты — тикер базовой валюты в верхнем регистре. У Binance Alpha тикер берётся из официального списка токенов по Alpha ID. В совпадениях возможны коллизии одноимённых активов и пропуски при разных тикерах одной монеты. Сопоставления по адресу контракта и ручных псевдонимов пока нет.
- На каждую монету выбирается один рынок для свечей и сигнала. Сначала выбирается котировка в порядке USDT, USDC, USD, BTC, ETH, затем остальные. При равенстве используется порядок Binance, Bybit, OKX, Bitget, MEXC, KuCoin, Gate, Binance Alpha, затем идентификатор пары. Наличие листинга проверяется по всем активным котировкам.
- Свечи строятся по REST API выбранного рынка. Видна история до 240 минут. Колесо мыши меняет масштаб, перетаскивание прокручивает историю, кнопка ↦ возвращает к свежим свечам. Видимые графики обновляются каждые 12 секунд.

## Сигналы и сетка

Все монеты из результата подписываются на публичные WebSocket-сделки выбранных рынков независимо от сетки. Для MEXC используются подписки Protobuf по 30 инструментов на соединение. Остальные рынки распределяются группами до 100 с учётом формата запросов биржи. Соединения переподключаются с увеличивающейся паузой. Статус показывает количество рынков в подключённых группах и сколько из них дали сделку за последние 15 секунд. Подключение группы отражает отправку подписки и состояние соединения. Свежесть конкретного рынка подтверждается только пришедшей сделкой.

Три независимых окна по умолчанию — 4% за 15 секунд, 5% за минуту и 20% за 15 минут. Базовая сделка берётся около начала окна с допуском ±3 с, ±8 с или ±30 с соответственно. Текущая сделка должна прийти не позже чем через 5 секунд от времени биржи. Начальные данные накапливаются после запуска. На малоликвидном рынке без подходящей пары сделок окно пропускается. Сигнал окна повторно разрешается после снижения измеренного роста ниже 75% от порога. Для одного инструмента также действует общая пауза 30 секунд. Для корректных отметок времени нужны синхронизированные часы Windows. Географические ограничения, лимиты соединений и проблемы сети могут уменьшать фактическое покрытие.

Сигнал записывается в журнал и открывает график в первой свободной ячейке. Заполненная сетка заменяет самый старый незакреплённый график. При полном закреплении сигнал остаётся в журнале. Сигнал по уже открытому рынку сохраняет его позицию. Ручной выбор фиксирует график. Кнопка закрепления позволяет менять его состояние. Сетки 2×2 и 3×3 используют общие первые четыре позиции. Журнал содержит до 200 событий за текущий сеанс.

## Сборка и обновления

Требуются Windows x64 и .NET 10 SDK для разработки. Готовый EXE включает нужный рантайм.

```powershell
dotnet run --project tests/ThinMarketMonitor.Checks -c Release
dotnet run --project tests/ThinMarketMonitor.Checks -c Release -- --live
dotnet publish src/ThinMarketMonitor -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o artifacts/publish
```

Пуш тега формата `vMAJOR.MINOR.PATCH` запускает Windows-сборку, автоматические проверки, запуск EXE и публикацию в GitHub Releases. Настройки проверяют последний стабильный релиз этого репозитория. При наличии новой версии кнопка скачивает EXE, сверяет размер и SHA-256 из метаданных GitHub, затем атомарно заменяет файл после выхода. Предыдущая версия сохраняется до подтверждения запуска новой. При сбое запуска выполняется попытка отката. EXE выпускается без подписи Authenticode. Для автоматического обновления используйте папку с правом записи.
