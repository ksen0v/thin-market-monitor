# Thin Market Monitor

Windows-приложение для фильтрации спотовых и фьючерсных рынков, мониторинга импульсов цены и объёма и просмотра свечей.

## Установка на Windows x64

- [Скачать Setup](https://github.com/ksen0v/thin-market-monitor/releases/latest/download/ThinMarketMonitor-Setup-win-x64.exe). Мастер устанавливает приложение для текущего пользователя без прав администратора. Папка по умолчанию — `%LOCALAPPDATA%\Programs\Thin Market Monitor`. Ярлык в «Пуск» добавляется автоматически, ярлык на рабочем столе можно выбрать в мастере. Приложение удаляется через «Установленные приложения» Windows.
- [Скачать portable EXE](https://github.com/ksen0v/thin-market-monitor/releases/latest/download/ThinMarketMonitor-win-x64.exe). Его можно запустить сразу. Для встроенного обновления нужна папка с правом записи.

Обе версии используют `%LOCALAPPDATA%\ThinMarketMonitor\settings.json`. Установка, обновление и удаление через Windows сохраняют этот файл.

## Фильтр и выбор рынка

- ✓ — активный листинг обязателен. Несколько ✓ дают пересечение.
- × — активного листинга быть не должно. Любая из бирж с × исключает совпадение.
- — — сегмент игнорируется при сравнении. Если ✓ нет, исходный список берётся из доступных спотовых каталогов, включая Binance Alpha, без отметок.
- У Binance, Bybit, OKX, Bitget, MEXC, KuCoin и Gate правила Spot и Futures задаются независимо. Binance Alpha настраивается отдельно. Правила прошлых версий переносятся в Spot.
- Кнопка сегмента переключает состояния —, ✓ и ×. Каталоги обновляются при запуске и каждые пять минут. При ошибке любого каталога с ✓ или × список и сигналы приостанавливаются. Состояние каталога видно на главном экране, подробности — в подсказке.
- Активные пары сопоставляются по базовой валюте. Например, `AKE-USDT`, `AKEUSDT` и `AKEUSDTM` соответствуют `AKE`. Binance Alpha берёт тикер из списка токенов по Alpha ID. Фьючерсные псевдонимы заданы явно для конкретных бирж. Совпадения тикеров могут объединить разные активы, если они используют одно имя.
- При наличии ✓ исходный рынок выбирается среди отмеченных сегментов. При наличии публичного потока сделки доступны для сигналов. Срочные контракты Gate Delivery доступны в каталоге и на графике, без потока сигналов. USD-оборот для расчётов по сделкам требует подтверждённого размера контракта.

## Графики и обзор

- Таймфрейм задаётся для каждого графика. Доступны 1, 5 и 15 секунд, 1, 5 и 15 минут, 1 и 4 часа, 1 день. В ячейках по умолчанию видны кнопки 15 с, 1 мин и 5 мин. Полный список открывается через кнопку таймфрейма. Стрелки вверх и вниз переключают периоды. Кнопки и клавиши настраиваются в разделе «Графики».
- При сдвиге влево история догружается страницами с сохранением видимой области. Глубина зависит от API биржи. Секундные интервалы используют биржевые секундные свечи или реальные сделки. Если биржа предоставляет только последние сделки, секундная история до начала наблюдения ограничена этой выборкой.
- ЛКМ внутри графика сдвигает время и цену. Сдвиг в будущее оставляет свободное место справа от последней свечи. Колесо масштабирует время, кнопка ↦ или двойной щелчок возвращает график к текущим свечам. Открытая свеча обновляется по WebSocket на рынках с потоком сделок. REST догружает историю и уточняет закрытые свечи. ЛКМ на шкале меняет только её масштаб, средняя кнопка включает линейку, F разворачивает активный график, F и Esc восстанавливают рабочую область.
- «Обзор» открывает отдельный график и таблицу активных инструментов выбранного сегмента. Таблица сворачивается значком у правого края. Клик по строке открывает график. По умолчанию таблица отсортирована по тикеру и показывает оборот в USD и изменение цены за 24 часа. В «Настройки → Обзор» можно настроить периоды и добавить ATR %. Он рассчитывается как средний True Range за период, делённый на последнюю закрытую цену. Сигналы продолжают работать в фоне.

## Фильтры объёма

Все включённые условия минимального объёма должны выполняться одновременно. Выберите 5 мин, 1 ч, 24 ч или период от 1 до 1440 минут. Проверяется оборот выбранного рынка. USD учитывается напрямую. USDT, USDC, FDUSD, TUSD, USDP, PYUSD и USD1 считаются по ≈ $1. Для остальных котировок пересчёт не выполняется.

Для 24 ч используются биржевые тикеры. Семь бирж обновляются одним запросом на биржу примерно раз в минуту. Binance Alpha запрашивается по одному рынку за раз. Остальные периоды суммируются по завершённым минутным свечам с минутным запасом на публикацию. Длинные запросы разбиваются на страницы, рынки обходятся с паузами и повторяются независимо от текущего допуска. На широких списках обновление занимает несколько минут, а старые и неполные результаты отображаются как ожидающие. Значения ниже порога и отсутствие данных обрабатываются по-разному. У KuCoin документированные пропуски между подтверждёнными краями окна считаются минутами без сделок. Неподтверждённые края оставляют окно неизвестным.

## Сигналы и сетка

Подписки на публичные WebSocket-сделки охватывают кандидатов после листингов, независимо от сетки. Сигналы и выбор инструмента ограничены итогом общего фильтра. Для MEXC используются подписки Protobuf по 30 инструментов на соединение. Остальные рынки распределяются группами до 100. Соединения переподключаются с увеличивающейся паузой. Статус учитывает подтверждения подписок и количество рынков со сделкой за последние 15 секунд.

«Импульс цены» включён по умолчанию. Пороги по умолчанию — 4% за 15 с, 5% за 1 мин, 12% за 5 мин и 20% за 15 мин. Прежние значения и переключатели сохраняются при обновлении. «Импульс объёма» включается в разделе «Модули». Его стартовые пороги — 100, 400, 2000 и 6000 USD за те же периоды. Каждая строка включается независимо. Дополнительные периоды задаются в секундах до одного часа.

Импульс цены использует две свежие сделки около границ окна. Импульс объёма суммирует цену × количество с дедупликацией по идентификаторам сделок. Суммы агрегируются по секундам с секундным буфером, а после разрыва соединения окно заполняется заново. Сигнал повторно разрешается ниже 75% порога. В каждом модуле действует пауза 30 секунд на инструмент. Готовность объёма в статусе относится к кратчайшему включённому окну. Синхронизация часов Windows, ликвидность, региональная доступность и лимиты бирж влияют на покрытие.

Сигнал открывает график в первой свободной ячейке. Заполненная сетка заменяет самый старый незакреплённый график. При полном закреплении сетка сохраняет текущие графики. Сигнал по уже открытому рынку сохраняет его позицию. Автоматически открытая ячейка показывает тип сигнала и кратко подсвечивается. Ручной выбор фиксирует график. Кнопка закрепления позволяет менять его состояние. Сетки 2×2 и 3×3 заполняют доступную высоту окна и используют общие первые четыре позиции.

## Сборка и обновления

Требуются Windows x64 и .NET 10 SDK для разработки. Готовый EXE включает нужный рантайм.

```powershell
dotnet run --project tests/ThinMarketMonitor.Checks -c Release
dotnet run --project tests/ThinMarketMonitor.Checks -c Release -- --live
dotnet run --project tests/ThinMarketMonitor.Checks -c Release -- --segments
dotnet publish src/ThinMarketMonitor -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o artifacts/publish
```

Пуш тега формата `vMAJOR.MINOR.PATCH` запускает Windows-сборку portable EXE и Setup, проверку установки, обновления и удаления, затем публикацию обоих файлов и `SHA256SUMS.txt` в GitHub Releases. Setup собирается с закреплённой версией [Inno Setup](https://jrsoftware.org/inno-setup/downloads).

«Настройки → О программе» проверяет последний стабильный релиз и сверяет размер и SHA-256 загружаемого файла с метаданными GitHub. Установленная копия скачивает Setup, проверяет его версию, обновляет приложение в текущей папке и запускает его снова. Если Setup завершился с ошибкой, приложение показывает код ошибки и путь к журналу установки, когда журнал доступен. Portable скачивает EXE, заменяет его после выхода и при сбое запуска пытается восстановить предыдущий файл. Оба файла выпускаются без подписи Authenticode.
